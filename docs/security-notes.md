# 보안 구현 메모 (로컬 샘플)

이 문서는 구현자가 보안 처리를 제3자가 확인할 수 있게 남긴 메모다. 설계서 docs/design.md는 바꾸지 않았다.

- 로그인 쿠키는 HttpOnly, SameSite=Lax 이다. 서명 키는 환경변수 또는 `.data/session-secret`에만 두고 저장소에 넣지 않는다.
- 변경 요청은 Origin이 이 사이트와 같거나, 화면에서 보내는 `x-requested-with` 헤더가 있어야 한다.
- 예약·문의·댓글의 소유권과 상태 변경은 데이터베이스 권한 규칙과 트리거가 막는다. 화면에서 숨기는 것에 기대지 않는다.
- 겹치는 예약은 `reservations_no_overlap` 배제 제약이 한 건만 저장하게 한다.
- 입력은 길이·형식·허용 값을 서버에서 검사하고, SQL은 파라미터로만 전달한다. 화면은 React 텍스트로 출력한다.
- 오류 응답에는 데이터베이스 문장을 넣지 않는다. 테스트 모드에서만 짧은 원인을 포함한다.
- 챗봇은 저장된 조문으로 근거를 고른다. 이 PC의 Ollama(127.0.0.1만)가 켜져 있으면 그 조문으로 답을 다듬고, 꺼져 있으면 조문 검색으로 돌아간다. 조문에 없는 숫자가 있으면 그 답을 버린다. `LLM_PROVIDER=claude`면 승인 전 함수가 호출을 거절하며 외부 네트워크로 나가지 않는다.
- API 키 자리는 `.env.example`의 빈 값뿐이다.
