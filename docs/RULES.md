# Claude·Cursor 협업 규칙 (서버가 있는 웹앱용 원본 규칙)

## 개발 순서
1. 기획 (Claude) — 이번 프로젝트는 docs/design.md 1~3장에 기획 내용을 포함한다
2. 설계 (Claude 단독) — docs/design.md
3. 구현 (Cursor)
4. 검수 (Claude)
5. 기능 테스트 (Cursor)
6. 인프라 (Claude)
7. 보안진단·모의점검 (Claude) — 가짜 데이터가 있는 테스트 서버에서만
8. 수정·재점검
9. 상용 배포 (사람 승인)
10. 오픈 (사람)

## 공통 규칙
- 기준 문서는 docs/design.md. 두 도구 모두 이 문서를 기준으로 작업한다.
- 한쪽 도구가 작업하는 동안 다른 쪽은 같은 파일을 고치지 않는다. 작업 시작·종료를 INBOX에 적는다.
- 요청·답변은 docs/handoff/INBOX.md 장부와 docs/handoff/requests/ 폴더에 파일로 남기고, 사용자에게 전달을 부탁하지 않는다.
- 테스트 오류는 재현 순서·기대 결과·실제 결과를 기록해 Cursor가 고치고, 같은 테스트를 다시 한다.
- 설계와 달라지는 수정은 멈추고 설계 문서를 먼저 고친다. design.md는 Claude만 고친다. Cursor는 요청 파일로 알린다. 큰 수정은 검수를 다시 받는다.
- 상용 배포, 비용이 생기는 작업(유료 API·LLM 호출 포함), 보안 설정, 비밀키, 삭제·결제는 사람이 승인한다. 에이전트의 보안 통과 의견은 참고용이다.
- 변경 이력은 Git으로 남겨 되돌릴 수 있게 한다.
