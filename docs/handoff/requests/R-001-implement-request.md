# R-001 구현 요청 (Claude → Cursor)

- 날짜: 2026-11-06
- 상태: 완료 (Cursor가 2026-11-06에 구현과 테스트를 마침. design.md v0.1 기준)
- 기준 문서: docs/design.md v0.1, docs/RULES.md

## 요청
design.md 10장의 1~4단계 순서대로 구현한다. 5단계(챗봇의 회의실 조회)는 이번 요청에 포함하지 않는다. 서브에이전트는 developer(구현), tester(기능 테스트)를 쓴다.
1. 프로젝트 생성(Next.js), supabase/migrations(8개 테이블, 권한 규칙, 중복 예약 방지 제약), 이메일 로그인, 역할(staff/admin)
2. 회의실 예약: 시간표, 예약 입력, 내 예약·취소, 관리자 방 관리. 샘플 방 3개
3. 헬프데스크: 문의 등록, 내 문의, 관리자 목록·상태 변경, 댓글
4. 챗봇: data/regulations/ 적재 스크립트와 질의응답 화면. 규정 원문은 공개 자료를 내려받아 출처(발행처·URL·기준일)를 기록해 저장한다

## 완료 기준
- design.md 11장 검수 확인 항목을 확인할 수 있는 테스트가 있다 (동시 예약, 남의 것 수정 불가, 상태 순서)
- 가짜(샘플) 데이터만 사용한다
- 설계와 다른 점이 있으면 구현을 멈추고 이 폴더에 요청 파일로 알린다

## 지켜야 할 것
- 사람 승인 없이 하지 않는다: LLM 호출(챗봇 4단계의 실제 호출), 유료 서비스 가입·결제, 비밀키 생성·저장, 상용 배포. 승인이 필요한 지점에서는 멈추고 요청 파일로 알린다
- 4단계에서 LLM 호출 없이 가능한 부분(규정 적재, 화면, 호출부를 가짜 응답으로 대체한 테스트)까지만 먼저 한다
- API 키는 서버 환경변수에만 둔다. 저장소에 넣지 않는다
- design.md는 고치지 않는다
- 작업 중인 파일은 INBOX 점유 표에 적는다

## Cursor 답변

2026-11-06 구현과 로컬 테스트를 마쳤다. `npm test` 19개 모두 통과. 화면 서버에서도 로그인, 예약, 겹치는 예약 거절, 문의 접수, 근로시간 질문을 확인했다. 자세한 케이스는 docs/test-report.md.

만든 것:
- Next.js 화면: 회의실 시간표·예약·내 예약·방 관리, 문의 등록·내 문의·댓글·관리자 상태 변경, 규정 챗봇
- supabase/migrations: 테이블 8개, 권한 규칙, 예약 겹침 배제 제약, 상태 순서 트리거, 샘플 회의실 3개
- data/regulations/labor-standards-act.json: 국가법령정보센터 근로기준법(시행 2026-10-08, 법률 제21533호) 조문 131개. 법률 조문은 저작권 보호 대상이 아니어서 텍스트만 저장했다.

승인이 없어 멈춘 곳 (설계를 바꾸라는 요청은 아님):
- Supabase 클라우드와 실제 이메일 비밀번호 로그인은 비밀키가 필요해 연결하지 않았다. 같은 SQL을 이 PC의 로컬 데이터베이스에 적용하고, 샘플 직원·관리자 두 계정으로 들어간다.
- 챗봇은 외부 AI를 호출하지 않는다. 저장된 조문만 찾아 답하고, 없으면 설계서의 확인 불가 문장을 그대로 쓴다. `LLM_PROVIDER=claude`여도 호출 전에 거절한다.
- 5단계(챗봇의 회의실 조회)는 만들지 않았다.

design.md는 수정하지 않았다.
