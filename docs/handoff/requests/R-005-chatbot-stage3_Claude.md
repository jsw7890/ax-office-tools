문제 (고칠 것)
1. **[중요] 시스템 문장에 평가 질문 주제가 들어가 있음.** `ANSWER_SYSTEM`에 "최저임금·육아휴직·실업급여"를 거절 대상으로 적었는데, 이는 R-004 검수용 질문 X01~X03 주제와 같다. 알려진 질문에 맞춘 것이라 수치가 실제 성능을 보여 주지 못한다. 또 제60조⑥3호처럼 조문 안에 육아휴직이 나오는 정상 질문("육아휴직 기간도 연차 출근으로 쳐?")을 잘못 거절할 위험이 있다. → 특정 주제 이름을 모두 빼고 "근거 조문에 답이 없으면 false"라는 일반 규칙만 남길 것.
2. **[확인 필요] `num_ctx` 2048이 근거 길이에 비해 작을 수 있음.** 근거 최대 약 3,000자 + 시스템 문장 + 질문 + 답 280토큰이면 한국어 기준 2048토큰을 넘을 수 있고, 넘으면 Ollama가 입력 앞부분을 잘라 지시문이 빠질 수 있다(qwen 범위 밖 거절이 낮은 원인일 가능성 — 추정, 미확인). → 응답의 `prompt_eval_count`를 문항별로 기록하고, 2048에 가까우면 4096으로 올려 다시 잰다.
3. **[문서] test-report R-005 표 안에서 빌드가 "성공"과 "본 회차 미실행"으로 엇갈림.** Claude가 빌드 성공을 확인했으니 "미실행" 문구를 고칠 것.
4. [작은 것] `buildEvidenceText`가 질문 임베딩을 한 번 더 만든다(최대 10초 추가). 검색 단계 임베딩을 넘겨 재사용할 것.

다시 잴 것
- 1·2 반영 후 두 모델 모두 같은 평가 질문으로 다시 측정, 표에 변경 전/후 함께 기록.
- 3단계 기준(범위 밖 4/4 그리고 잘못 거절 ≤2)은 그대로. 낮추지 않는다.
- 새 모델 내려받기는 하지 않는다(필요하면 JSW 승인 후).
- 검수용 질문(숨김 10문항)은 아직 실행하지 않는다.

보안 점검: Ollama 호출은 기존 loopback 주소만 사용, 챗봇 경로에 DB 쓰기 없음, 모델 답의 조문 번호는 검색된 조문 안에서만 허용, 숫자+단위 검사 통과 못 하면 조문만 보여 줌 — 문제 없음.
